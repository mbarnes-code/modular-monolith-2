# Configuration Guide

This guide covers configuring Goose for optimal performance with various LLM providers and extensions.

## Configuration File Location

Goose uses YAML configuration files located at:

- **Linux/macOS**: `~/.config/goose/goose.yaml`
- **Windows**: `%APPDATA%\Goose\goose.yaml`

## Basic Configuration

### Minimal Setup

```yaml
# ~/.config/goose/goose.yaml
default:
  provider: openai
  processor: gpt-4
  accelerator: gpt-3.5-turbo
```

### Complete Example

```yaml
# ~/.config/goose/goose.yaml
default:
  provider: openai
  processor: gpt-4o
  accelerator: gpt-3.5-turbo

# LLM Provider configurations
providers:
  openai:
    api_key: ${OPENAI_API_KEY}
    base_url: https://api.openai.com/v1

  anthropic:
    api_key: ${ANTHROPIC_API_KEY}
    base_url: https://api.anthropic.com

  ollama:
    base_url: http://localhost:11434

# MCP Server configurations
mcp:
  servers:
    filesystem:
      command: npx
      args: ['-y', '@modelcontextprotocol/server-filesystem', '~/Projects']

    github:
      command: npx
      args: ['-y', '@modelcontextprotocol/server-github']
      env:
        GITHUB_PERSONAL_ACCESS_TOKEN: ${GITHUB_TOKEN}

# Session settings
session:
  max_tokens: 8000
  temperature: 0.1

# Logging configuration
logging:
  level: info
  file: ~/.config/goose/logs/goose.log
```

## LLM Provider Setup

### OpenAI Configuration

1. **Get API Key**: Visit [OpenAI Platform](https://platform.openai.com/api-keys)
2. **Set Environment Variable**:
   ```bash
   export OPENAI_API_KEY="sk-your-key-here"
   ```
3. **Configure Models**:
   ```yaml
   default:
     provider: openai
     processor: gpt-4o # Primary model for complex tasks
     accelerator: gpt-3.5-turbo # Faster model for simple tasks
   ```

### Anthropic Configuration

1. **Get API Key**: Visit [Anthropic Console](https://console.anthropic.com/)
2. **Set Environment Variable**:
   ```bash
   export ANTHROPIC_API_KEY="sk-ant-your-key-here"
   ```
3. **Configure Models**:
   ```yaml
   default:
     provider: anthropic
     processor: claude-3-5-sonnet-20241022
     accelerator: claude-3-haiku-20240307
   ```

### Local Models with Ollama

1. **Install Ollama**: Follow [Ollama installation guide](https://ollama.ai/)
2. **Pull Models**:
   ```bash
   ollama pull llama3.1:8b
   ollama pull codellama:7b
   ```
3. **Configure Goose**:
   ```yaml
   default:
     provider: ollama
     processor: llama3.1:8b
     accelerator: codellama:7b

   providers:
     ollama:
       base_url: http://localhost:11434
   ```

### Multiple Provider Setup

```yaml
# Define multiple provider profiles
profiles:
  development:
    provider: ollama
    processor: llama3.1:8b

  production:
    provider: openai
    processor: gpt-4o

  budget:
    provider: openai
    processor: gpt-3.5-turbo
# Use specific profile
# goose --profile development session start
```

## MCP Server Configuration

### File System Access

```yaml
mcp:
  servers:
    filesystem:
      command: npx
      args:
        ['-y', '@modelcontextprotocol/server-filesystem', '/allowed/directory']
```

**Security Note**: Only grant access to directories you trust Goose to modify.

### GitHub Integration

```yaml
mcp:
  servers:
    github:
      command: npx
      args: ['-y', '@modelcontextprotocol/server-github']
      env:
        GITHUB_PERSONAL_ACCESS_TOKEN: ${GITHUB_TOKEN}
```

**Token Permissions**: Ensure your GitHub token has appropriate scopes (repo, workflow, etc.).

### Database Connections

```yaml
mcp:
  servers:
    postgres:
      command: npx
      args: ['-y', '@modelcontextprotocol/server-postgres']
      env:
        POSTGRES_CONNECTION_STRING: 'postgresql://user:pass@localhost/db'
```

### Custom MCP Server

```yaml
mcp:
  servers:
    my-custom-server:
      command: python
      args: ['-m', 'my_mcp_server']
      cwd: '/path/to/server'
      env:
        API_KEY: ${MY_API_KEY}
        DEBUG: 'false'
```

## Advanced Configuration

### Context Management

```yaml
session:
  max_tokens: 8000 # Maximum context window
  context_window: 6000 # Working context size
  summary_threshold: 4000 # When to start summarizing
  temperature: 0.1 # Response randomness (0.0-1.0)
```

### Performance Tuning

```yaml
performance:
  parallel_requests: 3 # Concurrent API calls
  retry_attempts: 3 # Failed request retries
  timeout: 30 # Request timeout (seconds)
  cache_responses: true # Cache LLM responses
```

### Security Settings

```yaml
security:
  allowed_hosts: # Restrict network access
    - 'api.openai.com'
    - 'api.anthropic.com'
    - 'localhost'

  sandbox_mode: false # Restrict file system access

  audit_log: true # Log all operations
  audit_file: ~/.config/goose/audit.log
```

## Environment Variables

Goose supports various environment variables for configuration:

### API Keys

```bash
export OPENAI_API_KEY="sk-..."
export ANTHROPIC_API_KEY="sk-ant-..."
export GITHUB_TOKEN="ghp_..."
```

### Configuration Overrides

```bash
export GOOSE_CONFIG_PATH="/custom/path/goose.yaml"
export GOOSE_DEBUG=true
export GOOSE_LOG_LEVEL=debug
```

### MCP Server Configuration

```bash
export MCP_SERVER_FILESYSTEM_PATH="/allowed/directory"
export MCP_SERVER_GITHUB_TOKEN="$GITHUB_TOKEN"
```

## Migration and Updates

### Upgrading Configuration

When updating Goose, your configuration may need updates:

```bash
# Backup current configuration
cp ~/.config/goose/goose.yaml ~/.config/goose/goose.yaml.backup

# Migrate configuration format
goose config migrate

# Validate migrated configuration
goose config validate
```

### Configuration Versioning

```yaml
# Include version for compatibility tracking
version: '2.0'

default:
  provider: openai
  processor: gpt-4o
  # ... rest of configuration
```

## Troubleshooting Configuration

### Common Issues

1. **Invalid YAML syntax**: Use online YAML validator
2. **Missing environment variables**: Check with `echo $VAR_NAME`
3. **Permission errors**: Verify file permissions with `ls -la`
4. **API key issues**: Test keys independently with curl

### Configuration Debugging

```bash
# Show loaded configuration
goose config show --debug

# Test specific provider
goose config test-provider anthropic

# Validate MCP servers
goose config test-mcp filesystem
```
