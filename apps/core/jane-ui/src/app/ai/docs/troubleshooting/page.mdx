# Troubleshooting Guide

This guide helps you resolve common issues with Goose installation, configuration, and usage.

## Installation Issues

### macOS Permission Problems

**Problem**: Goose Desktop won't launch on macOS, especially on M3 Macs.

**Symptoms**:

- App launches but no window appears
- Permission denied errors in logs
- Application crashes on startup

**Solutions**:

1. **Check ~/.config directory permissions**:

   ```bash
   ls -la ~/
   chmod 755 ~/.config
   ```

2. **Allow app in Security & Privacy**:
   - Open System Preferences → Security & Privacy → General
   - Click "Allow" next to the blocked Goose app
   - If not visible, try running the app first

3. **Grant Full Disk Access** (if needed):
   - System Preferences → Security & Privacy → Privacy
   - Select "Full Disk Access"
   - Click the lock icon and enter your password
   - Click "+" and add Goose app

4. **Reset app permissions**:
   ```bash
   sudo xattr -rd com.apple.quarantine /Applications/Goose.app
   ```

### Windows Antivirus Issues

**Problem**: Antivirus software blocks Goose installation or execution.

**Solutions**:

1. **Add exception for Goose directory**:
   - Open your antivirus settings
   - Add the Goose installation directory to exceptions
   - Common paths: `C:\Program Files\Goose\` or `%APPDATA%\Goose\`

2. **Temporary disable real-time protection**:
   - Only during installation
   - Re-enable after successful installation

3. **Download from official sources only**:
   - Use GitHub releases: https://github.com/block/goose/releases
   - Verify checksums if provided

### Linux Dependency Issues

**Problem**: Missing system dependencies on Linux.

**Symptoms**:

- "library not found" errors
- Segmentation faults
- GUI not rendering properly

**Solutions**:

**Ubuntu/Debian**:

```bash

    libnss3 \
    libatk-bridge2.0-0 \
    libdrm2 \
    libxcomposite1 \
    libxdamage1 \
    libxrandr2 \
    libgbm1 \
    libxss1 \
    libasound2 \
    libgtk-3-0 \
    libx11-xcb1
```

**CentOS/RHEL**:

```bash
sudo yum install -y \
    nss \

    at-spi2-atk \
    libdrm \
    libXcomposite \
    libXdamage \
```

## Configuration Issues

### LLM Provider Setup Problems

**Problem**: Can't connect to OpenAI, Anthropic, or other providers.

**Symptoms**:

- "API key invalid" errors
- Connection timeout issues
- Rate limiting errors

**Solutions**:

1. **Verify API key format**:

   ```bash
   # OpenAI keys start with "sk-"
   echo $OPENAI_API_KEY

   # Anthropic keys start with "sk-ant-"
   echo $ANTHROPIC_API_KEY
   ```

2. **Check API key permissions**:
   - Ensure key has necessary scopes
   - Verify account has sufficient credits
   - Check for IP restrictions

3. **Test connection manually**:

   ```bash
   # OpenAI test
   curl -H "Authorization: Bearer $OPENAI_API_KEY" \
        https://api.openai.com/v1/models

   # Anthropic test
   curl -H "x-api-key: $ANTHROPIC_API_KEY" \
        https://api.anthropic.com/v1/messages \
        --data '{"model":"claude-3-sonnet-20240229","max_tokens":10,"messages":[{"role":"user","content":"Hi"}]}'
   ```

4. **Update configuration file**:
   ```yaml
   # ~/.config/goose/goose.yaml
   default:
     provider: openai # or anthropic, ollama, etc.
     processor: gpt-4
     accelerator: gpt-3.5-turbo
   ```

### MCP Server Connection Issues

**Problem**: MCP servers not connecting or failing to start.

**Symptoms**:

- "Server not found" errors
- Tool calls failing
- Timeout errors during server startup

**Solutions**:

1. **Verify server installation**:

   ```bash
   # Check if MCP server is installed
   npx @modelcontextprotocol/server-filesystem --version

   # Install if missing
   npm install -g @modelcontextprotocol/server-filesystem
   ```

2. **Check configuration syntax**:

   ```yaml
   mcp:
     servers:
       filesystem:
         command: npx
         args:
           ['-y', '@modelcontextprotocol/server-filesystem', '/allowed/path']
   ```

3. **Test server independently**:

   ```bash
   # Run server manually to check for errors
   npx @modelcontextprotocol/server-filesystem /tmp
   ```

4. **Review server logs**:
   ```bash
   # Check Goose logs for MCP errors
   tail -f ~/.config/goose/logs/goose.log
   ```

## Runtime Issues

### Performance Problems

**Problem**: Slow response times or high resource usage.

**Solutions**:

1. **Check system resources**:

   ```bash
   # Monitor CPU and memory usage
   top -p $(pgrep -f goose)

   # Check disk space
   df -h ~/.config/goose
   ```

2. **Optimize configuration**:

   ```yaml
   # Use faster models for simple tasks
   default:
     accelerator: gpt-3.5-turbo # Instead of gpt-4

   # Reduce context window if needed
   context:
     max_tokens: 4000 # Instead of 8000
   ```

3. **Clear cache and logs**:

   ```bash
   # Clear old logs
   rm ~/.config/goose/logs/*.log.old

   # Clear cache (if applicable)
   rm -rf ~/.config/goose/cache/*
   ```

### Memory and Context Issues

**Problem**: Out of memory errors or context window exceeded.

**Solutions**:

1. **Start fresh session**:

   ```bash
   goose session start --new
   ```

2. **Reduce context size**:
   - Break large tasks into smaller sessions
   - Use `goose session clear` to reset context
   - Focus on specific files rather than entire projects

3. **Monitor token usage**:
   ```bash
   # Enable token usage logging
   export GOOSE_DEBUG=true
   goose session start
   ```

### Extension and Tool Failures

**Problem**: Specific tools or extensions not working.

**Solutions**:

1. **Check tool availability**:

   ```
   # In Goose session
   What tools are available to me?
   ```

2. **Verify file permissions**:

   ```bash
   # For filesystem operations
   ls -la /path/to/working/directory
   chmod 755 /path/to/working/directory
   ```

3. **Test individual tools**:
   ```bash
   # Test file operations
   echo "test" > /tmp/test.txt
   cat /tmp/test.txt
   rm /tmp/test.txt
   ```

## Network and Connectivity Issues

### Proxy and Firewall Problems

**Problem**: Can't connect through corporate network or proxy.

**Solutions**:

1. **Configure proxy settings**:

   ```bash
   export HTTP_PROXY=http://proxy.company.com:8080
   export HTTPS_PROXY=http://proxy.company.com:8080
   export NO_PROXY=localhost,127.0.0.1
   ```

2. **Check firewall rules**:
   - Allow outbound connections on ports 80, 443
   - Allow connections to API endpoints:
     - `api.openai.com`
     - `api.anthropic.com`
     - `api.together.xyz`

3. **Test connectivity**:

   ```bash
   # Test basic connectivity
   curl -I https://api.openai.com

   # Test through proxy
   curl --proxy $HTTP_PROXY -I https://api.openai.com
   ```

## Debug Mode and Logging

### Enable Debug Logging

1. **Environment variable**:

   ```bash
   export GOOSE_DEBUG=true
   goose session start
   ```

2. **Command line flag**:

   ```bash
   goose --debug session start
   ```

3. **Configuration file**:
   ```yaml
   # ~/.config/goose/goose.yaml
   debug: true
   log_level: debug
   ```

### Log File Locations

- **Linux/macOS**: `~/.config/goose/logs/`
- **Windows**: `%APPDATA%\Goose\logs\`

### Reading Log Files

```bash
# View recent logs
tail -f ~/.config/goose/logs/goose.log

# Search for errors
grep -i error ~/.config/goose/logs/goose.log

# Filter by timestamp
grep "2024-01-15" ~/.config/goose/logs/goose.log
```

   - Exact commands used
   - Expected vs actual behavior
   - Minimal example if possible

## Frequently Asked Questions

### Q: Can I use Goose offline?

**A**: Goose requires internet connectivity to access LLM providers. However, you can use local models with Ollama for offline operation.

### Q: How do I update Goose?

**A**:

- **CLI**: `goose update`
- **Desktop**: Re-run installer or use package manager
- **Homebrew**: `brew upgrade block-goose` or `brew upgrade block-goose-cli`

### Q: Can I run multiple Goose sessions?

**A**: Yes, each session is independent. Use `goose session start --new` to create additional sessions.

### Q: How do I backup my Goose configuration?

**A**: Copy the entire `~/.config/goose/` directory to backup all settings, logs, and session data.

### Q: Is there a way to limit API costs?

**A**: Configure budget limits in your LLM provider dashboard, use cheaper models for simple tasks, and monitor token usage regularly.
